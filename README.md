# AXIOM 节拍打点器

一个无需账户、依赖包或后端的中文静态应用。音频、波形与拍点都在浏览器本机处理；网页不会上传素材，不保存本地文件到服务端。

## 运行
用任意静态 HTTPS 主机部署本目录，入口是 `index.html`；本地测试可用 `python -m http.server 8765`，用浏览器打开 `http://localhost:8765`。直接双击文件可能被浏览器阻止加载 ES modules。npm 不是必需的。

## 使用
1. 选择或拖入浏览器可播放的文件，通常建议 WAV、MP3 或 M4A。
2. 点「播放」听音乐；默认按 F 或点绿色按钮在当前位置打点，包括暂停和触屏。可将按键换成 J／D／K。空格不再控制全局打点或播放。点击波形或移动进度条跳转，两秒步进用于复查。
3. 记录可点击定位，单条删除或清空都可撤销；也可用 Ctrl/⌘+Z。
4. 复制直接给出逐行原音秒数；CSV 和 JSON 可以选带对照网格的独立列，原测时间不会被替换。
5. 不用懂 BPM：点击「跟着音乐点四下」进入校准，听到想作为第 1 拍的地方后，点同一个按钮（也可按所选按键，默认 F）四次；四灯按这组间距循环，歌曲速度变化可以重校准。校准点不写入手打记录。实际记点和校准每拍都有按钮反馈；「敲击音」默认关闭，打开后仅在按下拍点时播放短促提示，不写入录音或导出。
6. 如需网格对照，填 BPM 和第一个下拍在原音中的时间，然后选择 1 拍、半拍或四分之一拍。正偏差表示标记晚于最近网格线。不是自动 BPM 识别。

换文件或关闭前先导出。素材只驻留当前页面，超 150 MB 不解码波形、但支持浏览器可播放文件的标记。大型文件和个别格式的波形生成受设备解码和内存限制。不同设备的触碰、按键反应和实际听感延迟会变，三位小数是储存精度，不是精密校准；最终以剪辑时间轴试听为准。

## 检查
`node --test tests/*.test.mjs` 验证原时间、网格、四拍校准、灯的循环、撤销及波形数据。可选的 Chromium 手动集成检查：安装 Playwright 并备有 /usr/bin/chromium 后，运行 `python tests/ui-smoke.py`，需允许本机回环端口。运行时文件为 `index.html`、`style.css`、`app.mjs`、`core.mjs`。

剪辑片段时间 = 原音拍点 − 该片段在原音的起始点。例：9.040−5.410 = 3.630 秒；还可以按剪辑工程的帧率取最近一帧。
